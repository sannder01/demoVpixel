# PIXEL CUBER CLUB — деплой с облачным хранением броней

Данные о местах (свободно/занято) теперь хранятся в **Vercel KV**
(Redis-совместимое хранилище от Vercel) через серверлесс-функцию
`/api/pcs`. Все посетители сайта видят одно и то же состояние.

## Шаги подключения

1. **Загрузите этот проект в GitHub** (или залейте прямо через Vercel CLI/веб-интерфейс) —
   структура должна остаться такой:
   ```
   index.html
   api/pcs.js
   package.json
   ```

2. **Создайте Vercel KV**:
   - Откройте ваш проект в панели Vercel → вкладка **Storage**
   - Нажмите **Create Database** → выберите **KV**
   - Дайте название (например, `pixel-cuber-kv`) и создайте

3. **Подключите KV к проекту**:
   - После создания хранилища Vercel предложит **Connect to Project** —
     выберите ваш проект `pixel-cuber-club`
   - Vercel сам добавит нужные переменные окружения
     (`KV_REST_API_URL`, `KV_REST_API_TOKEN` и т.д.) — вручную ничего вписывать не нужно

4. **Переразверните проект** (Redeploy), чтобы переменные окружения подхватились.

5. Готово — открывайте сайт, бронируйте место в панели пользователя,
   и статус сохранится в облаке. Если открыть сайт с другого устройства
   или обновить страницу — состояние будет тем же.

## Как это работает

- `api/pcs.js` — серверлесс-функция:
  - `GET /api/pcs` — вернуть текущее состояние всех мест (создаёт начальный набор, если хранилище пустое)
  - `POST /api/pcs` с телом `{ id, status }` — обновить статус конкретного места
  - `POST /api/pcs` с телом `{ reset: true }` — сбросить все места в "свободно" (удобно для тестов)

- `index.html` — фронтенд без изменений в дизайне, но теперь:
  - при заходе в панель пользователя/администратора данные загружаются через `fetch('/api/pcs')`
  - бронирование/изменение статуса отправляется через `fetch('/api/pcs', { method: 'POST', ... })`
  - есть кнопка **Обновить** и обработка ошибок сети

## Дальнейшие шаги (по желанию)

- **Авторизация** сейчас проверяется на клиенте (демо-логины). Чтобы сделать её настоящей,
  можно добавить `api/login.js` и хранить пользователей в той же KV или в Vercel Postgres,
  а сессию выдавать через JWT/cookie.
- **История броней** (кто и когда бронировал) можно добавить отдельным ключом в KV,
  например `bookings:log`, куда дописывать записи при каждом POST.
- Если нужна более "настоящая" реляционная база (с датами, ценами, клиентами) —
  логичный следующий шаг — **Vercel Postgres** вместо KV.
